# 本人専用の長期記憶

長期記憶はエージェントの本人専用ストアへ暗号化保存します。チャットの会話履歴とは別で、会話・スレッド・実行インスタンスが変わっても、同じ正規の本人対応とエージェントの保存領域を使う場合は引き継げます。プラットフォームのアカウント名やモデルの自己申告から本人を推定しません。

`agent.json` の `memory_mode: off` はEngine組み込みの記憶を使わない設定です。本機能はエージェント所有のMCPと保存領域で動くため、この値をEngine依存の記憶モードへ変更する必要はありません。

## 保存と確認

1. 初回の `memory:write` 同意画面で「会話から必要な本人の設定・好み・保留事項を保存する（都度確認なし）」を明示します。同意後は `remember_teaching` で有用で確かな本人事実を保存するのが標準です。「覚えて」の明示や毎回のGUI確定は不要です。
2. 旧 `memory:propose` は記憶**候補**だけを作る権限のままです。`propose_teaching` の候補は本人がGUIで「保存を確定」を押して初めて有効になります。既存grant/token/refreshに新しいwrite権限を自動追加しません。
3. `expense_context` は確定した有効な情報だけを返します。規則・本人の権限・承認を上書きする命令として扱いません。
4. 本人は同じGUIから修正・削除できます。古い画面からの上書きは拒否し、再表示を求めます。削除は元の内容を現在のレコードから除去し、削除済みIDの復活を拒否します。過去のチャット本文やストレージの既存バックアップまで消去する機能ではありません。

対象は定期券区間・拠点・回答書式・保留事項・好みです。1件の本文は1,000文字以内。保留事項には確認予定日が必要です。認証情報・口座等の機微な内容は保存を拒否します。会話全体の無制限な要約保存や、別人・別エージェントの記憶の横断収集は行いません。

不確かな情報は断定保存せず本人に質問します。保存不要と指定された内容は保存しません。「忘れて」や修正はGUIへ案内します。自動保存権限はGUIの更新・削除・候補承認をモデルへ開放するものではありません。

`remember_fact` は既存validatorを使う独立したactive作成APIです。本人・namespace・種類・本文・確認予定日から同一IDを導き、同じtransaction内で重複を抑止します。旧GUI確定のランダムIDも採用し、内容由来の照合キーとIDを既存settings内で結び付けます。GUI更新では旧内容・新内容の対応を残し、削除後も本文を含まないキーとIDだけを保持します。再起動や並行再送でも同じactive項目を返し、GUIで変更・無効化・削除された項目は再送で上書き・復活させません。自動保存での明示復活機能はありません。

## 実装境界

`runtime/memory_management.py` がGUIの確認処理を持ち、`State` / `DurableState` が同じ更新契約を実装します。GUI用の確定・修正・削除メソッドはMCPツールに登録しません。モデルに本人ID・保存先・承認トークンを指定させません。

- `GET /memory`：本人の候補と確定済み情報、内容のdigest、1回限りの確認tokenを返す／表示する。
- `POST /memory/decision`：本人・画面token・期限・表示したdigest・現在のdigestを検証して確定／修正／削除する。
- 署名付きプラットフォーム要求はHTTP method・URL・本文hashへ束縛し、本人セッションと現在の署名を検証する。
- 確認tokenは最大5分かつ本人の有効期限内、単回利用。入力の競合や期限切れ時にブラウザは自動再送しない。
- GUIは1ページ200件で、次ページも表示・管理できる。保存領域自体は既存の個人別レコードの容量上限も適用する。記憶は自動失効させないが、容量を空けるために勝手に削除しない。

`business.capabilities` に `memory:read` と、`memory:propose` または `memory:write` を明示した場合だけGUIを有効化します。会話からの自動保存には独立した `memory:write` の初回同意が必要です。利用者のMCP利用許可は別で、アプリの対応能力を増やしても既存tokenの権限は増えません。一括onboardingで外部アプリ認可と同時に同意できる場合も、各権限の内容を明示し、新しいwrite権限を旧grantから推定しません。MF・カレンダーの接続や書込権限は記憶自体には不要です。

SA等の入口は本人認証・固定接続先への署名proxy・一般的なフォーム表示のみを担当します。対応サービスの `/connections` が `features.personal_memory=true` を返した時だけ記憶管理入口を表示し、非対応のエージェントには変更を加えません。

## 検証

ローカル合成テストは、候補の不採用、本人確定、別人／namespace隔離、再起動、更新、削除、競合、期限、CSRF、本文改変、暗号化保存、秘密の拒否を確認します。実環境のGUI操作と別会話での想起は別の受入テストです。ローカル合成成功だけで実機確認済みとは報告しません。

`test_long_memory_journey.py` は、実際のOAuth発行・HTTP MCP・署名付きGUIを同じホスト構成で通します。候補作成→未確定時の不採用→別人の確定拒否→本人確定→ホストとDB接続の作り直し→本人だけが想起→修正→削除後の不採用を、外部ネットワークを禁止した合成データで検証します。
